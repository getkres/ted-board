# Card reconciler design

The user has supplied the required behavior and authorized implementation through a PR and reviewed private patch. This design makes the remaining engineering calls. Nothing is installed, deployed, or applied by this card.

Use a small Python reconciler, rather than introducing a hosted workflow engine. A two-minute, level-triggered pass observes the live board, durable session store, approvals, local reports and SQL artifacts, mockup feed, and GitHub PR evidence. It produces deterministic actions before executing anything. Dry-run is the default and never invokes dispatcher ticks, controls, model workers, archive writes, or database writes. Missing or partial observations fail closed and appear as coverage defects.

Every open entity has one owner (`ted`, `sebastian`, `worker:<id>`, or `external`) and a stable next-action deadline. Cards get database defaults and constraints; the ledger covers jobs, approvals, PRs, SQL packets, and mockup batches. A deadline is advanced by a real transition, never by a poll or cosmetic update. Missing owner or deadline is a visible defect. Age starts when an action starts, not at the most recent heartbeat. Ted escalation occurs at 2 hours, a repeated Ted escalation and board banner at 12 hours, and Sebastian escalation at 24 hours only for an explicitly classified reserved decision. Review SLA is 6 hours, oldest first.

Worker leases last 150 seconds and renew every 30 seconds from the wrapper, using its turn, PID identity, and fencing token. A completed result is consumed before lease failure. An expired lease is dead even if its process exists. Its matching process group must be stopped and verified absent before a new attempt. Never retry email, spend, approved SQL execution, veto delivery, or an uncertain side effect. Ordinary work retries at most twice with deterministic exponential backoff and jitter, then enters a durable Ted dead-letter queue. Redrive requires an explicit Ted command and a reason. Actions and receipts survive restart; repeated reconciliation cannot create duplicate turns, notes, or build cards.

The shared capacity.json retains the live 64-worker total and load guard at twice CPU count, with separate base Opus 2 and Sonnet 8 worker caps. Verified, enabled account 2 selects the configured 4/16 caps. Reviews are exempt from model worker caps, remain subject to global and host limits, and do not consume model worker slots. Missing capacity or host observation fails closed. The 8 GiB available-memory guard and two urgent reserved slots remain. Managed passes attempt at most ten launches and three retry launches. Oldest work goes first, and structured priority breaks equal-age ties. Ted must verify actual throughput in the documented soak.

Approved mockups produce a deterministic build card and durable chain: approved, build, PR, merged, deployed, verified. A PR URL alone proves only a PR exists. GitHub merge evidence advances to deployment ownership; a structured deployment receipt advances to verification; a separate verification receipt tied to that merged commit and the current card revision closes the chain, after workers settle. Missing evidence holds the stage with Ted and a deadline. Existing exact linked build cards are reused. Archive policy remains owned by PR 41 and does not erase approval lineage.

The backend change is a private Edge Function patch plus unapplied SQL and rollback. Authenticated page reads expose an aging ledger; only the worker credential publishes it. All new public tables explicitly grant CRUD to service_role, enable RLS, and revoke public, anon, and authenticated. The Jobs view shows every open entity, owner, age, due date, and overdue text with red styling. Missing data and a stale reconciler remain visible.

The existing board_live two-minute launchd entry point becomes the sole reconciler entry point after Ted installs the patch. The heartbeat still publishes health and processes existing controls, but does not independently dispatch or reap while reconciler mode is enabled. The watchdog and inbox steward must defer overlapping recovery to the same loop. The hourly lead loop reads the ranked Ted queue before its quiet gate and drains at least two items. No new routine is created, and all installation is mini-only.

The failure-routing card owns the underlying inbox policy. Its patch will be treated as a required dependency, not overwritten. This card adds queue-level fencing and tests to prevent its reconciler from putting operational failures in needs_you. Sebastian's allowed kinds are spend, sends, contracts, pricing, gated production writes, fresh taste picks, and his copy. Matching rules must still be resolved through the existing guarded path. Routine failures, PR reviews, retries, SQL preparation defects, and archived mockups belong to Ted.

Integration refinements: a shared durable enable file fences watcher dispatch as well as launchd entry points. Slow publication and outbox transports run outside the lease lock. Recovery retains newly queued requests, refuses any persisted uncertain veto, verifies the whole process group is gone, and never retries verified delivery. Optional-feed failures preserve prior obligations, and uncertain taste classification cannot remove a current ask. Historical stage transitions are monotonic, so late PR evidence cannot backdate into a rejected publication.

Final race guards: consume remote controls before observation, recheck a fenced result immediately before recovery, settle explicit stops without retry, retain established delivery stage when files are lost, require authoritative Jobs and ledger reads before publication, and synchronize priority into persisted sessions before admission.

Ted review refinement: per-pass effect budgets cap retries at 3, Ted routings at 5, new cards at 5, delivery advances at 5, dispatch proposals at 10, and escalations at 10. All initial escalation proposals collapse into one deterministic ranked digest, with atomic covered receipts. Sensitive original decision scope and personal authentication block automatic inbox routing even when a progress line appears operational.
