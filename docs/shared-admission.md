# Shared admission for the mini

This PR stages one resource gate for board workers, direct command entry points, and model launchd wrappers. It is a private-runtime review packet, with generic source/test patches and synthetic public fixtures. Nothing is installed by merging this public repository. Do not start another routine to run it.

## Policy

Every cooperating caller uses the same installed module and `~/ted-ops/state/shared-admission`. The gate holds one flock across evidence collection, reservation, child creation, and durable state replacement. Proposed defaults are:

- Load admission: measured one-minute load, plus one CPU unit for each existing reservation, plus the proposed run's one CPU unit, must be at most twice the host's CPU count.
- Memory admission: measured available bytes, minus every existing two GiB reservation, minus the proposed run's two GiB reservation, must leave at least the larger of four GiB or 10% of physical memory.
- Each reservation persists while any non-zombie process in its process group survives. An absent leader does not free capacity while its children remain.

On macOS, available memory is free, inactive, and speculative pages from `vm_stat`, using its reported page size. Compressed and wired pages are excluded. Linux CI uses `MemAvailable`. Unknown counters, failed process evidence, corrupt state, non-private directories, symlinks, and incompatible lease policy defer admission. State and lock files are private. No command arguments or environment values are recorded.

Reservations deliberately double-count some measured demand. This is a conservative first policy, not a throughput optimum or a guarantee of a process's peak memory. Measure completion rate, queue age, actual memory peaks, and deferral rate before tuning the central policy. A process can exceed its declared reservation. Existing unwrapped work affects measured pressure but has no reservation, and load averages lag bursts. The board retains its 64-session and provider lane ceilings. Legacy `capacity.json` remains unchanged at a three-times-core load ceiling and engine ceilings of four Claude and sixteen Sonnet workers. The new shared resource gate is the stricter effective load policy for cooperating new starts: measured load, existing CPU reservations, and the next reservation must fit within twice the CPU count. Its memory policy can be stricter still. Legacy silent pre-loop load checks are removed from candidate source so the shared gate records its refusal. Managed `runner_admission` remains a separate queue and engine eligibility filter, including urgent slot reservations and review exemptions from engine ceilings. Those exemptions do not bypass the hard shared host resource budget. Managed host observations can refuse work before it reaches the shared gate; those existing holds retain their existing reporting behavior.

The launcher starts a small helper in a dedicated process group. The helper verifies its own PID, start identity, and committed reservation under the same lock before executing the requested command. Failed persistence cannot run the command. If a supervisor disappears, remaining group members keep the reservation. A live group leader with a different stored start identity proves reuse and releases that stale reservation, including after a reboot. Commands that deliberately detach into another session escape that group; do not route daemonizing commands through this wrapper without a separate ownership design.

Signal forwarding for TERM, INT, and HUP is installed before admission begins, with a no-op before a child is assigned, and the prior handlers are restored on return. SIGKILL cannot be forwarded. In the supplied heartbeat adapter, the existing `perl` alarm remains inside the supervised group and bounds that command to 5400 seconds even if the wrapper is killed. This bound applies to that adapter, not every command: board workers retain their existing twelve-hour model timeout, the queued-task wrapper retains its own timeout, and other direct callers must select an appropriate command timeout.

## Entry points

Apply `shared-admission-tools.patch` only in an isolated review tree. Install `scripts/shared_admission.py` and the explicit package marker in the private board runtime after review. If PR 43 already installed `scripts/__init__.py`, preserve that equivalent package marker rather than applying a duplicate creation blindly.

`shared-admission-sessions.patch` is retained only for the historical synthetic dispatcher contract. Do not apply it to current private runtime files. `runner-fix/prepare_shared_admission.py` strictly adapts both current legacy dispatcher methods and the managed `reconciler_sessions.py` worker launch. It refuses missing or duplicate worker surfaces and already-adapted source, returns candidate text without installing it, and preserves unrelated code. Review the generated diff against the exact live and managed baselines. Both the legacy dedicated account lane path and the flag-off path use the shared helper. On deferral, it restores the exact queued turn, clears transient veto authority, resets a review to approved, and revalidates the approved artifact on the next tick. Refused starts also clear `active_turn`, unstarted model leases, and active lane execution fields. Durable work and review account affinity and an existing valid review resume identity remain intact. A subsequent tick validates the approved artifact before preparing its lane again. Managed dispatch and retry counters, including lifetime automatic dispatch counts, increment only after successful shared admission. Only capacity deferrals stop the dispatch loop. Unavailable evidence leaves that turn queued and continues to later eligible sessions. A hard launch error, including a missing cwd or failed helper `Popen`, fails only its session with the existing could-not-start response. Input preparation is inside the same launch-error boundary. Unexpected programming exceptions are not disguised as deferrals. The worker's existing store-lock identity handshake remains in place. No model, approval execution, or timed send is launched by a refused admission.

Deferrals carry one of three fixed reason codes: `LoadCapacity`, `MemoryCapacity`, or `EvidenceUnavailable`. Evidence errors add only an exception class name, never its message or arguments. The current cause appears in the queued session's `last_line` and stderr. Consecutive attempts for the same turn retain their first timestamp and count. After 15 minutes, the affected existing card receives a blocked live status with the safe cause, once per episode. Failed publication is retried on the next tick. Admission or a hard launch failure clears the episode. This reuses the work card, creates no duplicate card or routine, and makes no Needs you transition.

`codex-heartbeat-admission.patch` wraps the existing model heartbeat runner as lane `launchd`. `prepare_shared_admission.adapt_company(source)` routes only the actual model-producing launch inside the current company coordinator through the same helper as lane `launchd`. It preserves task selection, subscription authentication, account environment, arguments, process-group cleanup, and timeout behavior. Health probes, bookkeeping, and acceptance checks retain their existing execution path. The supervising compatibility shell stays unchanged, so the coordinator and child are never double-reserved. The earlier outer-only shell patch is retired because its detached model group could outlive its reservation if the coordinator died. `direct-browser-admission.patch` wraps the direct browser chore command as lane `direct`. The adapters preserve existing prompts, timeouts, task selection, command arguments, and redirections. They propagate the actual exit status, including deferral code 75. Refused company admission returns the exact unstarted task to ready, fences the previous claim token, releases only its own task resource reservations, retains its immutable specification and prepared evidence, and records a safe deferral event. A started task or stale token cannot use this path. It creates no success artifact, external message, or automatic retry. They do not enable a schedule or alter launch agent configuration.

Use the same wrapper for other direct Ted commands:

```sh
python3 "$HOME/ted-ops/ted-board/scripts/shared_admission.py" run --lane direct -- command argument
```

Use `--lane launchd` for other reviewed model-producing launchd commands. Health, status, watchdog, queue bookkeeping, and renewal checks stay outside the model admission gate so pressure does not prevent observation. The lane is descriptive, not a different allowance. Production callers must use the default state directory; `--state-dir` exists for isolated tests and is a bypass if used in production.

A deferral does not create a success artifact. Board work stays queued. Direct commands return 75 for capacity or unavailable evidence. A missing executable returns 127, and a non-executable or otherwise failed exec returns 126, with a distinct class-only diagnostic. Helper `Popen` errors retain their original `OSError` for the board's could-not-start handling. When an uncommitted helper does not exit after TERM and a ten-second wait, cleanup sends KILL to its owned group and reaps it. A second bounded wait failure is an evidence deferral, not an uncaught `TimeoutExpired`. The existing launchd wrappers preserve these statuses, and their next-run or catch-up handling must be confirmed during rollout. This gate does not add durable scheduling or claim that a daily job will retry automatically.

## Rollout and rollback

Back up each private source file and its current mode. Inventory the existing queue eligibility and account lane filters, and preserve them. Every cooperating start additionally passes the same shared resource helper; the shared budget does not replace lane or managed lifecycle authority. Apply the two shell adapters with `patch --dry-run --fuzz=0` against their actual current files. Use `prepare_shared_admission.adapt(source, managed=False)` for the actual legacy lane and pause source, and `adapt(source, managed=True)` for managed sessions. Do not stack the historical sessions patch. Refuse drift, inspect the generated diff, record before and after SHA-256 hashes, and reconcile drift in review. Install the helper and explicit package marker before either importing adapted dispatcher. Preserve existing helper modules from other packets. Run the source-specific harness before installation, then install the same reviewed helper and adapters on the mini. Existing running jobs are not killed or retroactively registered. Verify a low-pressure start, a pressure deferral with the same turn still queued, approved-artifact revalidation, a surviving-child reservation, and exit status propagation. Do not execute real approvals or external sends as a smoke test.

Inventory every model-producing entry point, including application scheduler jobs and ad hoc raw CLI calls, before claiming universal coverage. The supplied adapters cover the inspected board dispatcher, direct browser helper, model heartbeat runner, and queued-task compatibility wrapper. Arbitrary raw CLI calls and application-owned scheduler launches remain bypasses until routed through the common wrapper. This is staged code, not a claim of host-wide enforcement.

Rollback restores the backed-up adapters first. Stop or allow admitted children to finish before removing the helper. Retain the state directory and lock inode while any caller uses them. Do not delete a reservation to force a start; investigate its recorded process group.

## State repair and operating limits

A corrupt or incompatible lease file fails closed. It is not a reason to delete a reservation or switch production callers to another state directory. To repair it, pause all producing entry points, let admitted work finish, preserve a timestamped private copy of the entire state directory, and compare a complete fresh process-group inventory with the recorded owners. Resume only after every recorded group is verified absent and every caller uses the same reviewed policy. With no surviving owners and no new starts possible, rebuild the empty state under the existing lock. Keep the original state and lock inode for audit, and refuse repair if ownership evidence is incomplete. Policy changes need the same drained transition.

The wrappers use dedicated process groups. Stopping a wrapper does not by itself establish that its group is gone. Calendar launchd deferral still returns 75 and does not create catch-up scheduling. The actual compatibility launcher in the private Fictora checkout delegates to its company coordinator; the mini staging shim delegates to that same launcher. Install the reviewed inner `company.py` candidate after its fixed helper path exists, and preserve the outer launcher byte for byte. The generic adapter refuses unrecognized source surfaces. Verify the generated diff and before and after hashes against the actual checkout before installation. No new routine is part of this packet.

The separate company admission harness uses a disposable actual coordinator and temporary SQLite ledgers. It verifies refusal without model execution or a failed-task notification, exact task readiness and claim fencing, actual model PID reservation with literal arguments, timeout descendant cleanup, stale and started claim refusal, and non-model checks outside the model budget. Run it with:

```sh
python3 runner-fix/company_admission_runtime_test.py --company-source /absolute/disposable/company.py --helper-root /absolute/disposable/adapted-runtime
```

The direct Codex and heartbeat adapters execute the CLI, or the existing exec-preserving perl timeout, in the reserved group. They do not introduce another session boundary before that CLI. Arbitrary subprocesses or future application launchers that detach remain outside this packet's declared caller coverage and require their own ownership review.
